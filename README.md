# GitHub Awesome 系列导航

这是一份按主题整理的 GitHub Awesome 清单导航。Awesome 项目通常由社区持续维护，用来汇总某个领域中值得关注的库、工具、教程、论文和实践资料。

> 本文是精选入口，不追求穷尽。仓库的 Star 数和更新时间变化很快，因此不在文档中记录这些数据。原人工核对日期：2026-08-11；这不是逐条 URL 的实时可用性证明，具体观察结果见下方可选审计。

## 如何继续发现

1. 先从 [sindresorhus/awesome](https://github.com/sindresorhus/awesome) 的分类目录查找主题。
2. 在 GitHub 搜索 `awesome + 关键词`，再结合 `awesome-list` Topic 筛选。
3. 检查仓库最近提交、Issue 和 Pull Request，确认清单仍在维护。
4. 比较同一主题下的多个清单；优先选择分类清晰、链接检查自动化、贡献规范完整的项目。

## 收录建议

新增条目时建议满足以下条件：

- 内容是经过筛选的主题清单，而不是未经整理的链接堆积。
- 仓库公开可访问，说明清晰，链接仍然有效。
- 优先收录持续维护、社区参与活跃、具有明确贡献规范的项目。
- 使用 `名称 + GitHub 链接 + 一句话说明` 的格式，并放入最贴近的分类。


## 可选 URL 审计

README 决定收录与分类；审计 JSON 仅记录一次观察，不自动改动条目，也不记录 Star 数。
使用 Python 3 标准库脚本，无需安装依赖。默认完全离线，为每个去重后的条目生成
`skipped / network_not_requested`，不会假定链接可用：

```sh
just audit-links > link-audit.json
# 或从任意目录调用脚本，默认仍读取本仓库 README
python3 scripts/audit_links.py > link-audit.json
```

需要实际 HTTP 证据时显式启用检查；可重复 `--url` 分批选择索引中的 URL。
每次输出都是完整索引的独立快照，未选中或超过本次配额的条目仍有明确跳过原因；
历史报告可另存为带日期的文件，本工具不合并或假称保留了历史检查结果。

```sh
python3 scripts/audit_links.py --check \
  --url https://github.com/sindresorhus/awesome \
  --max-checks 10 --timeout 5 > link-audit.json
```

检查按索引顺序串行进行，默认最多检查 10 个条目（允许 0–100），每个条目最多
跟随 5 次重定向。只发 HEAD、不读取响应正文、不自动重试；每次请求的 socket 超时
默认为 5 秒（允许大于 0 且不超过 60 秒），不是 DNS 或整次运行的严格时限。
保留系统代理与 TLS 证书验证。未执行 `--check` 的测试和报告没有外部网络请求。

报告 `entries` 以规范 URL 为键，同时保留全部原始 URL、名称、README 行号及源文件
SHA-256。规范化只处理协议/主机大小写、默认端口、空路径 `/` 和移除 fragment；
路径大小写、尾部斜杠、查询参数保持不变，不推断 GitHub 仓库别名或维护状态。
解析范围是表格第一列的 `[名称](HTTP(S)-URL)`；正文链接和代码围栏内示例不算条目。
不支持的表格语法、凭据 URL 或无条目会报错退出，避免生成不完整但看似成功的报告。

每个条目都有 `status`（`checked`、`failed`、`skipped`）、`reason`、UTC 时间及重定向列表。
`recorded_at` 是报告生成时间；离线条目的 `attempted_at`、`checked_at`、`http_status`
均为 null。只有实际请求才填写尝试时间，只有收到 HTTP 响应才填写对应的观察时间与
状态码；每个重定向有来源、目标、HTTP 状态和观察时间。`final_url` 是最后尝试的地址，
不保证访问成功。2xx 为 `checked`；404/410 为本次 `http_not_found` 观察，不能直接
推断仓库永久死亡。429 单列为 `rate_limited`，408/425/5xx 与网络故障标记
`retryable: true`，不要据此删除条目。401/403 表示访问被拒；405 标为
`skipped / head_not_supported`，不额外发 GET。末次 HTTP 响应包含 `Retry-After` 时照实记录。

脚本成功生成完整报告时退出 0，即使部分 URL 检查失败；参数、输入或解析失败退出 2，
不输出成功报告。`just test` 全部使用离线解析 fixture 和内存 HTTP 响应，检查提取、
去重、跳过原因、重定向上限、状态分类和响应关闭；不验证互联网可用性。
